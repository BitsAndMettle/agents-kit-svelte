# agents-kit-svelte

## 0.2.0

### Minor Changes

- 3eadcf8: New token `--ak-color-scrim`: the backdrop behind modal dialogs and sheets, in light and dark.
- 792ac53: Theming: every colour, radius, font and shadow is now a public `--ak-*` token, declared in an `agents-kit` cascade layer so host CSS wins without `!important`. Tokens can be set on `:root` or on any wrapper, and `[data-theme="system"]` follows the OS colour scheme. The chat accent now follows the main accent unless `--ak-chat-accent` is set.
  
  Each component merges your `class` last with tailwind-merge, so your utilities replace the kit's. The helper is exported as `cn()` from `agents-kit-svelte/primitives`.
  
  Deprecated: the `--color-*-val` variables still work as overrides in this release and are removed in the next minor.
- 90514c6: Add the Auth account group: `AccountMenu`, `SessionList`, `VerifyEmailBanner` and `BackupCodes`. `DropdownMenu` gains an optional `header` snippet.
- 6c88619: Auth building blocks: AuthCard, PasswordInput (reveal, Caps Lock warning, rule checklist, strength meter), OtpInput (one real input drawn as cells), ProviderButton and PasskeyButton.
- 355d695: Add the Auth recovery group: `ForgotPasswordCard`, `ResetPasswordCard` and `TwoFactorSetup`.
- b8d8c8f: Auth sign-in group: `SignInCard`, `SignUpCard`, `MagicLinkSent` and `TwoFactorCard`.
- 8d6f1fd: Add `BlockedWorkList` to Agents UI Orchestration and `FeatureProposalCard` to Charts & Timelines. `BlockedWorkList` answers "what is stuck, and what can I do about it?": items are grouped by why they are stuck, each shows only the actions you pass for it, an action with a `confirm` sentence asks inline before `onAction` fires, and `busyIds` (or `busy` on an item) shows a spinner. `FeatureProposalCard` shows a Feature an agent proposes with its child cards: the person can remove or rename cards and write a note before `onApprove`, `onRevise` or `onDecline`, dependencies show as "after #2" chips, and the card is read-only once approved. Both are registered for `IntelligentUIRenderer`, and `groupBlockedWork` and the proposal helpers are exported for custom views.
- bbe38d5: `Button` gains `softDisabled`: the button looks disabled and reports `aria-disabled="true"` but keeps keyboard focus, and clicks are ignored. Use it for a wait such as a resend cooldown, where `disabled` would drop focus to the page.
- fe510c5: Add the Charts & Timelines collection (`agents-kit-svelte/charts`): `GenerativeChart` draws line, area and bar charts from a JSON spec an agent emits, with callouts; `AgentHandoffGantt` shows which agent held the work and what it handed on; `ModelPhaseStream` shows which model ran each phase, with escalation, fallback and swap markers. Every span, handoff, lane, phase, marker and point is clickable through your own handler (`onSelectSpan`, `onSelectHandoff`, `onSelectLane`, `onSelectPhase`, `onSelectEvent`, `onSelectPoint`), and handoffs carry a `kind` and a `data` payload so a click can open the diff, tests or file that was passed. All three are registered for `IntelligentUIRenderer`, share new `--ak-chart-1` to `--ak-chart-6` colour tokens, and come with scale and run-replay helpers and sample data in `agents-kit-svelte/fixtures`.
- 41b17f3: Rename `TrailsideClaudeChat` to `ChatWorkbench`. `TrailsideClaudeChat` still works as a deprecated alias and will be removed in the next major release; replace the import to move over:
  
  ```diff
  - import { TrailsideClaudeChat } from 'agents-kit-svelte/chat';
  + import { ChatWorkbench } from 'agents-kit-svelte/chat';
  ```
- 1d2da5d: Add collection entry points: `agents-kit-svelte/chat`, `/github`, `/skills`, `/workflows`, `/generative`, `/data`, `/effects`, `/primitives`, `/core` and `/fixtures`. The root import still exports every component and helper.
  
  Breaking: the site-only `CATALOG_ITEMS` catalogue and `validateSvelte5ComponentSource` audit are no longer part of the package, and the skill sample data (`SAMPLE_SKILLS` and friends) moved from the root to `agents-kit-svelte/fixtures`. `sideEffects` now lists only CSS.
- 792ac53: Components no longer fall back to demo data. Lists default to empty, the main label or record a component shows is required, and descriptions, timestamps and stats are hidden when not passed. Demo loops (`live`) are off by default. All the old samples are exported from `agents-kit-svelte/fixtures`.
  
  Every component now forwards extra attributes (`id`, `aria-*`, `data-*`, `style`, handlers) to its root element. `AgentToolPalette` builds its category tabs from the tools you pass (`ToolCategory` is now `string`), with `categoryLabels` and `defaultSelectedId`.
- 02e4cd5: Export the data types declared inside components (for example `AgentTask`, `SubAgent`, `ParallelLane`, `EvalIteration`, `InsightCard`, `FormField`) from `/chat`, `/data`, `/effects` and `/workflows`, as well as the package root, so you can type the data you pass in. The catalogue's usage examples now use the real props and types, and the install test type-checks every one of them.
- bf4df15: Add `FeatureCard` and `FeatureLineage` to the Charts & Timelines collection. `FeatureCard` summarises one Feature: acceptance criteria met with a progress sparkline, its cards split by state (click a segment to filter), attempts, PRs and tokens against budget. `FeatureLineage` lays out a Feature, its cards, agent attempts, PRs, releases and incidents as a graph: hover a node to trace its ancestry, fold a branch away, and click a node through `onSelectNode` to open what is behind it. Both are registered for `IntelligentUIRenderer`, and `layoutLineage` and `traceLineage` are exported for custom views.
- 6c534ec: Add `FeatureTimeline`, `TokenBurnChart` and `RunReplayScrubber` to Charts & Timelines. `FeatureTimeline` plots a Feature's cards planned against actual, with a forecast for running work, milestones, a forecast ship date, and sorting by slip. `TokenBurnChart` shows spend against a budget with the burn rate, a projection to the end, and where the budget runs out. `RunReplayScrubber` is a play, scrub and skip-between-moments control whose bindable `now` drives your charts; the `/charts` page now uses it. Adds the `formatDay` and `projectBurn` helpers.
- b6ee9e9: New `agents-kit-svelte/headless` entry: accessible behaviour without markup or styles, built on `<dialog>`, `popover` and CSS anchor positioning with no runtime dependencies. Patterns: `Dialog` (and alert dialogs), `Popover`, `Menu` (submenus, checkbox and radio items, context menus), `Select`, `Combobox`, `Listbox`, `Tooltip` (shared delay), `Tabs`, `Accordion`, `RadioGroup`, `ToggleGroup`, plus `ListNav` for custom composites. The peer dependency on Svelte rises to `^5.29.0` (attachments in spreads).
- bb88dd0: New in `agents-kit-svelte/chat`: `LevelDial` and `RiskToggle`, two controls for how far an agent may go on its own.
  
  `LevelDial` shows ordered autonomy levels (for example Careful, Balanced, Trusted, Autopilot) as a keyboard-friendly track, with what the selected level does on its own and what it still asks about. Selecting only previews. Moving up asks for a confirm that names what the level newly allows; moving down applies in one press. It is controlled: pass `value`, handle `onChange(levelId, { direction })`, and pass the new value back. `levelChanges()` and `levelDirection()` are exported helpers.
  
  `RiskToggle` is a switch for a risky setting. Turning it the risky way opens the risk points and an "I understand" checkbox, and the confirm button stays disabled until it is ticked; `onChange(next, { acknowledged })` reports the choice. The safe direction applies at once. Both are registered for `IntelligentUIRenderer` as `level-dial` and `risk-toggle`, and sample data is in `SAMPLE_AUTONOMY_LEVELS` and `SAMPLE_RISK_TOGGLE` (`agents-kit-svelte/fixtures`).
- f194100: Add `MetricTiles` to Charts & Timelines and `PresenceBanner` to the chat collection. `MetricTiles` shows a row of headline numbers (two across on a phone, four on a desktop): each tile can carry a unit or a duration or percent format, the change against the prior period coloured by which direction is better, a small trend line, or a "4 of 6" capacity bar, and becomes a button through `onSelect`. `PresenceBanner` is a slim `role="status"` banner for whether something you depend on is reachable (online, not responding, offline or reconnecting), with since-when as clock time and relative time from a `now` you pass in, an optional action such as Move or Retry, and an optional dismiss. Both are registered for `IntelligentUIRenderer`, and the `sparkline`, `metricDelta`, `describeMetric`, `relativeTime` and `clockTime` helpers are exported.
- 4159523: Two cards for an operator agent talking to a person in a chat thread. `DeviceApprovalCard` lets someone approve a new device (such as a phone) to act with the same rights as this one: a large match code read digit by digit to screen readers, the abilities it will get, time left, an "the code on my phone is …" check that must be ticked before Approve turns on, one-press Deny, and a one-line outcome afterwards. `CitedAnswer` shows an agent's answer to a question with each source as a quote and a check badge (verified, not checked, or quote not found); a mismatch raises a banner and hides Send. Both are in the `chat` entry and the Intelligent UI registry as `device-approval` and `cited-answer`, with pure helpers (`groupCode`, `speakCode`, `timeLeft`, `formatRequestedAgo`, `summarizeSources`) and samples in `agents-kit-svelte/fixtures`.
- d585d37: Two cards for running a fleet of agents from a phone. `FleetStatus` (workflows entry) lists the machines that run agent work: presence and last seen, busy slots as "4 of 6" with a segmented bar, what runs on each machine (collapsed to "+N more"), warning chips for missing safeguards, the machine the operator agent lives on, and a summary header. `ActionReceipt` (chat entry) is one record of something an agent did or refused to do, with the reason, who did it, the run that proposed it and an Undo that shows while it is done; use `compact` for inbox rows. Both are registered in the Intelligent UI registry as `fleet-status` and `action-receipt`. New types: `Machine`, `MachineWork`, `MachineFlag`, `ActionTarget`, `ActionOutcome` and friends, plus the `fleetSummary`, `slotSegments`, `relativeTime` and `workPreview` helpers.
- 3b3f738: PR flow components for driving a pull request from the chat: `GitHubPrActionBar` (Create PR with a diff stat and per-file menu), `GitHubPullRequestGraph` (a PR card with its commit graph and merge status), `GitHubChecksWaterfall` (live CI bars on one time axis, the failing assertion inline, Fix and Merge buttons) and `AgentWorkTrace` (a collapsible trace of what the agent did). All four are registered in the Intelligent UI registry as `github-pr-action-bar`, `github-pr-graph`, `github-checks-waterfall` and `agent-work-trace`.
- 766bcd4: Primitives: added the action components `Button`, `IconButton`, `ButtonGroup`, `Toggle` and `ToggleGroup`. Buttons cover five variants, four sizes, a pill shape, icon slots and a loading state that keeps the button's width and stays focusable; they render a link when given an `href`. `IconButton` requires an accessible `label`. `Toggle` and `ToggleGroup` bind their state, and `ToggleGroup` is built on the headless group pattern, so arrow keys, Home and End move focus.
- b25f3b3: Adds the display primitives, exported from `agents-kit-svelte/primitives`: `Badge`, `Avatar`, `AvatarGroup`, `Card`, `Separator`, `Kbd`, `Skeleton`, `Spinner`, `Progress`, `Alert` and `EmptyState`. Avatars fall back to initials or an icon when the image fails, a clickable `Card` has a single tab stop, `Alert` is announced only when you set `live`, and `Skeleton` and `Spinner` stand still under reduced motion.
- 7188a0b: Primitives: form controls. `Field` gives one control its label, `description`, error and required or optional mark; the kit controls inside it take its id, description, invalid and required state by themselves, and its children snippet hands the same attributes to any other element. The error is announced politely when it appears, and `<Field group>` renders a fieldset and legend for a RadioGroup or several checkboxes. A Checkbox or Switch with its own label keeps that label as its only name inside a Field. `Input` (leading and trailing content, a clear button), `Textarea` (auto-grow, a character count that speaks only near the limit, worded by `formatCount` and `formatRemaining`), `Checkbox` (indeterminate), `Switch` (`role="switch"`), `RadioGroup` (built on the headless RadioGroup), `NativeSelect` and `Slider` are native controls that work in a plain `<form>`: they post their name and value, `required` blocks a submit with focus on the visible control, and a form reset restores `defaultValue` (or `defaultChecked`), else the value they started with. Every control takes `bind:value` or `bind:checked`, `onValueChange` or `onCheckedChange`, `invalid` and a bindable `ref`; form-row controls take `size` (`sm`, `md`, `lg`). `getFieldContext` and `fieldControlAttrs` let your own controls join a Field.
- 36b08fb: Primitives: menus and pickers, styled over the headless layer and exported from `agents-kit-svelte/primitives`.
  
  - `DropdownMenu`: a menu button whose rows are data (`MenuEntry`: items with icon, shortcut hint, `tone` (`UiTone`) and `onSelect`; checkboxes; radio groups; headed groups; separators; nested submenus). `triggerLabel` for the default button, or a `trigger` snippet whose part already carries your attributes and `ref`. `open`/`defaultOpen`/`onOpenChange`, `placement` (`'bottom-end'` or a full placement), `menuClass`.
  - `ContextMenu`: the same rows on a region (`children`); right-click opens at the pointer, Shift+F10 or the ContextMenu key at the focused element. `menuLabel` names the menu.
  - `Select`: one value or several (`multiple`, shown as chips or a `formatCount` summary), options with groups, descriptions and disabled states, `value`/`defaultValue`, `size`, and `name`/`required`/`disabled`/`invalid` so it works in a plain form. Reads a surrounding `Field`. Extra attributes and `ref` go to the trigger.
  - `Combobox`: a filtering text input with a clear button (`clearLabel`), an empty state, a `filter` prop (or `false` for options you filter yourself), `bind:query`, a `loading` state (`aria-busy`), free text with `allowCustom`, and form props; `required` needs a chosen value, not just text. Reads a surrounding `Field`. Extra attributes and `ref` go to the input.
  - `CommandPalette`: a modal search over grouped commands (`label`, `description`, icon, shortcut hint), a Recent section and an empty state, opened by a global shortcut (`mod+k` by default) while it is mounted. When several palettes share a shortcut, the most recently mounted one answers it.
- c2520e3: Add the navigation primitives: `Tabs` (underline or segmented, automatic or manual activation, lazy panels), `Accordion` (single or multiple, find-in-page reveal), `Breadcrumb` (folds its middle behind a "…" button on narrow screens) and `Pagination` (buttons or links, compact "Page 3 of 12" on phones), plus the `paginationRange` helper. They wrap the headless layer.
- 08367cc: Primitives: overlays. `Dialog` (sizes sm, md, lg and full-on-phones; title and description wired for screen readers; header, body and footer snippets with a scrolling body; `bind:open`, `onOpenChange`, `initialFocus`, `dismiss`), `AlertDialog` (`role="alertdialog"`, focus starts on Cancel, `tone` (`UiTone`), async `onConfirm` with a loading state and inline error), `Sheet` (slides from the right, left, bottom or top, safe-area aware, drag handle on bottom sheets), `Popover` (anchored, flips, optional arrow that keeps pointing at the trigger when the card shifts, `placement` shorthand such as `"top-start"`, `matchWidth`) and `Tooltip` (delay group, closes first on Escape, string or snippet content). All are built on `agents-kit-svelte/headless`, animate with CSS only (`@starting-style`, `transition-behavior: allow-discrete`) and skip motion under reduced motion. Every overlay takes `open`/`defaultOpen`/`onOpenChange` (Tooltip follows hover and focus only) and a bindable `ref` to its surface; every visible string is a prop with an English default.
- b9ec936: `IntelligentUIRenderer` takes a `registry` prop: map node types to your own components (or replace the built-in ones) with `defineUIRegistry()`. Built-in node types live in `defaultUIRegistry`. Nodes missing a required prop, or naming an unknown type, render a short note. The renderer no longer invents sample data for nodes that omit props, and it now passes every node prop through to the component.
  
  New in `agents-kit-svelte/core`: `fromGitHubRest.issue`, `.pullRequest`, `.checkRun` and `.commit` map GitHub REST responses to the card types, with `formatRelativeTime`, `formatDuration` and `labelTone` helpers.
  
  Types: `DynamicUINode.component` and `SupportedAgentId` accept any string. `GitHubPullRequestData.riskTier` and `refereeStatus` are optional, and `PlanCard` shows a risk badge only when `riskTier` is passed.
